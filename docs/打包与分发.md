# 打包成独立 exe（免装 Python，双击即用）

> 目的：把启动方式从「双击 .bat（需系统装 Python 3.12+、首次要建 venv 装依赖）」
> 变成「双击 `PomExpress.exe`」。产物形态与 m7 的 exe 版一致：**一个文件夹 + 一个 exe**。

---

## 一、构建（一条命令）

**产物必须落在项目外部** —— `dist/`（约 460 MB）+ `build/`（约 80 MB）属构建副产物，
不放进项目根（项目根只放项目本体）。

```powershell
cd "F:\dsh workspace\STAR\PomExpress"
F:\dsh workspace\STAR\PomExpress_local\m7_venv\Scripts\python.exe -m PyInstaller PomExpress.spec --noconfirm `
 --distpath "F:\dsh workspace\STAR\_build\PomExpress\dist" `
 --workpath "F:\dsh workspace\STAR\_build\PomExpress\build"
```

- 首次需装 PyInstaller：`F:\dsh workspace\STAR\PomExpress_local\m7_venv\Scripts\python.exe -m pip install pyinstaller`
- 构建耗时约 3–5 分钟
- **产物路径**：`F:\dsh workspace\STAR\_build\PomExpress\dist\PomExpress\`
- `.gitignore` 里的 `dist/`、`build/` 保留作兜底（万一有人直接用默认路径跑）

**产物**（实测 2026-09-12）：

| 项 | 大小 |
|---|---|
| `PomExpress.exe` | **24.4 MB** |
| `dist/PomExpress/`（含 `_internal/`） | **463.6 MB** / 3440 文件 |

体积主要来自 PySide6 + onnxruntime + opencv + rapidocr。

## 二、运行（用户视角）

1. 把整个 `dist\PomExpress\` 文件夹拷给用户（**不能只拷 exe**，`_internal/` 必须一起）
2. 双击 `PomExpress.exe`
3. 首次启动会**请求管理员权限**（UAC）——输入注入需要提权；
 拒绝提权则以浏览模式启动（可看界面，不能执行任务）
4. 首次启动会在 exe 同级**播种**一份可写的 `knowledge\`（约 2.8 MB）

**首启后 exe 同级会多出这几项**（都是运行时数据，删了会重置状态）：

```
PomExpress.exe ← 主程序
_internal\ ← 依赖与只读资源（knowledge/assets 的原始副本）
knowledge\ ← 可写副本：用户录制的轨迹、自定义地图点位
logs\ ← 运行日志/crash dump
state\ ← 任务完成状态（runtime.db 等）
```

## 三、打包版与源码版的差异

### 3.1 两个「根」——只读资源 vs 可写数据

打包后有两个不同的根，由 `config/settings.py` 区分：

| 常量 | 打包后位置 | 放什么 |
|---|---|---|
| `RESOURCE_ROOT` | `sys._MEIPASS`（临时解包目录，**退出即删**） | 只读资源：`knowledge/`、`assets/`、`VERSION` |
| `DATA_ROOT` | **exe 同级目录** | 可写数据：`logs/`、`state/`、`memory/`、`failure_reports/`、`runtime.db`、`settings/*.ini`、`knowledge/` 可写副本 |

> **关键约束**：`sys._MEIPASS` 是 PyInstaller 的临时解包目录，进程退出即删除。
> 往它写数据 = 数据在退出时**静默丢失**。所以**写数据一律走 `DATA_ROOT` / `data_path()`**，
> 不要用 `ROOT`（`ROOT` 的语义是 `RESOURCE_ROOT`）。

**源码模式下 `DATA_ROOT == RESOURCE_ROOT == 仓库根`**，因此上述区分不改变源码行为
（改造后 `pytest tests` 仍为 421 passed）。

### 3.2 knowledge 的「播种」机制

`knowledge/` 整体是只读资源，但其中两类内容必须可写：

- `knowledge/trajectories/` —— 用户手动录制的轨迹
- `knowledge/guides/maps/08_custom/` —— 自定义地图点位（`guides_loader` 动态同步）

故打包环境首次调用 `settings.knowledge_root()` 时，会把包内的 `knowledge/`
**拷贝一份**到 `DATA_ROOT/knowledge` 并后续一律使用该副本
（`app/launcher.py` 启动早期即触发，早于任何知识包读取）。

### 3.3 已在代码中处理的打包特例

| 位置 | 处理 |
|---|---|
| `app/preflight.py::check_python_env` | 打包版跳过（自带解释器与依赖，没有 m7_venv，否则误报 critical 弹框拦住启动） |
| `app/launcher.py::_check_venv` | 打包版跳过 venv 提示 |
| `gui/run.py::_elevate_if_needed` | frozen 下只传 `argv[1:]`（源码模式下 `argv[0]` 是脚本路径必须原样传；打包后它是 exe 路径，再传一遍会被新进程当多余参数），工作目录固定为 exe 目录 |
| `gui/pages/world_graph.py` | 文件对话框起始目录改用 `DATA_ROOT`（不能用临时解包目录） |

## 四、应用图标

图标源文件：项目根 `logo.webp`（474×474，白底）。**未直接使用 webp**（Windows exe 资源与 Qt 都不吃 webp），
已转换为两个派生文件（均在 `assets/`，随包分发）：

| 文件 | 尺寸 | 用途 |
|---|---|---|
| `assets/logo.ico` | 内含 **16/24/32/48/64/128/256** 七档 | exe 资源管理器图标 + 窗口/任务栏图标 |
| `assets/logo.png` | 512×512 | `.ico` 缺失时的回退 |

**接线点**：
- `PomExpress.spec` 的 `EXE(icon="assets/logo.ico")` → exe 文件图标
- `gui/run.py` 创建 `QApplication` 后 `app.setWindowIcon(QIcon(app_icon_path()))` → 窗口/任务栏图标
- `config/settings.py::app_icon_path()` → 统一解析（打包/源码都正确）

**重新生成图标**（换 logo 时）：

```powershell
F:\dsh workspace\STAR\PomExpress_local\m7_venv\Scripts\python.exe -c "from PIL import Image; s=Image.open('logo.webp').convert('RGB'); b=s.resize((512,512), Image.LANCZOS); b.save('assets/logo.png','PNG',optimize=True); b.save('assets/logo.ico',format='ICO',sizes=[(16,16),(24,24),(32,32),(48,48),(64,64),(128,128),(256,256)])"
```

> **设计说明（保留白底的理由）**：应用主题是深色（`gui/theme.py` 的 `BG_DEEP = #0B1524`），
> 而 logo 内容包含较暗的部分（中心像素约 `(50,49,54)`）。若把白底抠成透明，暗部在深色
> 任务栏/标题栏上会**几乎看不见**；保留白底可保证在任何背景下都清晰。
> 若希望改为透明底（例如另做一版亮色描边的图标），换 logo 后重跑上面的命令即可。

## 七、重新打包的注意事项

1. **改了 `PomExpress.spec` 里 `datas` 的资源，或改了 `knowledge/`**，需要重新构建才会生效
2. **`--noconfirm`** 会直接覆盖 `dist/`，无需手动清理；若要干净重建先删 `dist/`、`build/`
3. **exe 不会自动更新** —— 源码改动后必须重新构建分发
4. 若构建后启动报缺模块，用 `F:\dsh workspace\STAR\PomExpress_local\m7_venv\Scripts\python.exe -m PyInstaller PomExpress.spec --log-level WARN`
 查看 `build\PomExpress\warn-PomExpress.txt`
