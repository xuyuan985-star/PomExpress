# 视角闭环控制设计说明

## 问题

当前轨迹回放的视角控制是**开环**的：录制时记录归一化鼠标位移 `(view_dx, view_dy)`，
回放时按客户区尺寸换算像素、按 `game_sensitivity` 比例缩放后直接发射。

这条路径有两个无法自纠正的误差源：

1. **游戏内灵敏度（`game_sensitivity`）不是完整的换算关系**。实际「鼠标像素位移 → 视角转动角度」
   还取决于鼠标硬件 DPI、Windows 指针速度设置、游戏分辨率与 FOV 设置。任一不同，换算即失真。
2. **误差会累积**。一帧偏离几度，几十个视角事件后轨迹就与录制时的实际路径分离，
   而回放过程中没有任何反馈来发现或修正偏离。

结果是：同一份轨迹在不同机器、或同一机器不同时间回放，落点不确定。**录制回放不可重复成功。**

## 参考：成熟方案的机制

外部参考实现 是生产可用的同类工具（GPL-3.0，本设计仅借鉴机制，不复制其代码）。
它的做法是**闭环**：

1. **测量实际朝向**（`utils/get_angle.py`）：截取小地图区域，用 HSV 青色掩膜分离方向箭头，
   取轮廓最远顶点相对中心的角度 → 得到人物当前朝向角。
2. **校准换算系数**（`utils/handle.py` 的 `set_angle`）：正转 60°、反转 60°，
   分别测量实际转过的角度，得到本机「鼠标位移 → 角度」的换算关系，而非依赖配置值。
3. **回放前回正**（`handle_view_reset`）：以录制时的初始朝向为目标，迭代旋转直到角度误差
   收敛到阈值以内，再开始执行轨迹。

关键点：**目标不是"发多少像素"，而是"转到什么朝向"**。朝向是可测量的，像素位移不是。

## 设计

### 模块划分

新增 `runtime/input/view_angle.py`，职责单一：从截图中测量朝向角度。

```
measure_angle(image) -> AngleResult
    AngleResult.available: bool      # 检测是否可用
    AngleResult.degrees: float|None  # 可用时的角度（-180..180）
    AngleResult.reason: str|None     # 不可用时的原因（供调用方决策与日志）
```

检测流程：截取小地图区域 → 转 HSV → 青色掩膜 → 找轮廓 → 验收（见下）→
取最远顶点 → 相对区域中心求 `atan2`。

**验收条件**（不满足即返回 `available=False`，不猜值）：
- 轮廓数量必须为 1（多个候选说明画面异常，例如小地图被遮挡或箭头被识别成多块）；
- 轮廓面积需在合理范围内（排除噪声与整屏色块）；
- 最远顶点到中心的距离需大于最小半径（避免退化成一个点）。

### 校准

```
class ViewCalibrator:
    calibrate() -> CalibrationResult   # 求得 pixels_per_degree
```

流程：记录当前角度 → 发射固定像素位移 → 再次测量角度 → 由「实际转角」与「发射像素」
求 `pixels_per_degree`。为提高稳健性，正反各做一次并取平均；两次方向的结果差异超过阈值
则判定校准失败（环境不稳定，例如游戏未获得焦点）。

校准结果**每次回放会话重新求取**，不落盘复用——因为鼠标 DPI 与指针速度设置在会话之间可能变化。

### 回放前回正

```
align_to(target_degrees, tolerance, max_iterations, timeout) -> bool
```

迭代：测量当前角度 → 计算与目标的最短角差（`(d + 180) % 360 - 180`）→
换算成像素位移并发射 → 重新测量。收敛到 `tolerance` 内即成功。

**保护**：`max_iterations`（默认 5）与 `timeout`（默认 10 秒）任一触发即返回失败，
并输出可见日志（包含每次迭代的角度、角差与发射像素）。

### 集成

`runtime/input/replayer.py` 的视角事件处理处：

- **有角度检测能力时**：每次视角事件改为「设定目标角度」语义——把录制时的
  `(view_dx, view_dy)` 位移先叠加到一个内部朝向估计上，得到目标角度，再用闭环转过去。
- **无角度检测能力时**：回落到现有的开环像素位移路径。

两条路径都必须保留，**不得破坏现有开环行为**（在无游戏窗口或检测不可用的环境下仍可回放）。

录制侧：轨迹元数据增加**初始朝向角**字段（可选）。录制时若检测可用则记录；
回放时若轨迹带该字段则据此回正，否则以回放开始时的朝向为基准。

## 验证（无游戏窗口环境）

本环境没有游戏窗口，因此用两层合成验证：

1. **检测精度**：程序化构造已知角度的方向箭头图（旋转同一模板到 N 个已知角度），
   对每个图调用 `measure_angle`，要求误差 ≤ 5°。
2. **闭环收敛**：构造一个模拟相机——其状态是当前朝向角，接受「像素位移」并提供
   截图（按当前角度渲染箭头图），像素到位角的换算系数由测试指定且**不告知被测代码**。
   然后要求：
   - `calibrate()` 求出的 `pixels_per_degree` 与测试设置值的相对误差 ≤ 5%；
   - `align_to(target)` 从任意初始角度收敛到 `tolerance` 内；
   - 检测不可用（模拟相机返回遮挡画面）时，`calibrate`/`align_to` 返回失败且日志可见，
     **不得静默继续**。

测试必须**能变红**：例如把 `measure_angle` 改成恒返回固定角度，检测精度与闭环收敛测试
都必须失败。

## 未决问题

**长轨迹中途是否周期性校正**：静态回正只能保证起点一致，回放过程中的偏离仍会累积。
周期校正（每 N 秒或每个视角事件后校验）理论上更可靠，但每次测量都有开销（截图 + 图像处理），
在轨迹密集处可能影响时序。当前决定：**先实现起点回正**，把周期校正作为可选开关，
待真机录制回放实测漂移速率后再决定默认值。此结论标记为待验证。
