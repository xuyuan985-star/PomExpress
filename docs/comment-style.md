# 代码注释规范

本文件规定本仓库注释与文档字符串（docstring）的写作要求，适用于 `runtime/`、`gui/`、
`ingest/`、`app/`、`config/`、`knowledge/*.py` 下的全部 Python 源文件。

## 目的

注释的作用是**让后续维护者理解代码为什么这样写**，而不是记录这段代码是何时、由谁、
在第几轮修改中产生的。过程性信息属于版本控制与提交历史，不属于源码。

本仓库早期存在大量过程性注释（修改轮次、任务编号、会话标记），既无维护价值，
也使代码看起来像临时草稿。本规范用于逐步清理。

## 注释应当写什么

| 类型 | 示例 |
|---|---|
| 设计原因（为什么这么做） | `# 该判定必须 fail-closed：宁可不下发动作，也不可误动作` |
| 接口契约 | `# 返回归一化坐标，范围 [0, 1]；越界值由调用方钳制` |
| 单位与坐标系约定 | `# 单位：像素，相对于游戏客户区左上角` |
| 平台限制 | `# Windows 下文件句柄未关闭时无法再次打开，必须先 close 再读取` |
| 边界条件 | `# 空列表时返回 0，不抛异常` |
| 算法依据 | `# 多尺度匹配 21 级：覆盖 1280 宽降采样后的常见缩放` |
| 已知限制 | `# 当前不支持执行中途暂停，需上层逐步骤检查` |

## 不应出现的内容

| 类别 | 反例 | 应改为 |
|---|---|---|
| 修改轮次 | `# round3 t3 修复：...`、`# R1 修复（行为恢复）：...` | 只写技术事实：`# 深度为 1 的文件，其父目录的父目录即仓库根` |
| 任务编号 | `# DS 加固（t1）：...`、`# #44：workflow 步骤类型白名单` | `# workflow 步骤类型白名单` |
| 缺陷编号 | `# Bug 83：单目标恢复/重试尝试硬上限` | `# 单目标恢复与重试的次数上限` |
| 会话与流程 | `# 本夜`、`# 队长`、`# 各席`、`# 交付`、`# 验收`、`# 探针` | 删除；测试相关术语只出现在测试文件中，且不记录会话过程 |
| 口语与情绪 | `# 踩过的坑`、`# 坑：`、`# 假绿`、`# 白干`、`# 玄学` | `# 已知约束`、`# 注意事项`，并说明具体技术原因 |
| 第一人称 | `# 我们在这里...`、`# 让我...` | 改为无主语陈述：`# 此处...` |
| 表情符号 | `# ✅ 已接线`、`# ❌ 不支持`、`# ⚠️ 注意` | 删除符号，用文字表达：`# 已接线`、`# 不支持`、`# 注意` |
| 强调滥用 | `# 绝对不能！！！`、连续破折号 | 平铺直叙，必要时用「必须/禁止」 |
| 未完成承诺 | `# TODO: 以后再说`、`# 暂不管` | 要么实现，要么写成明确的已知限制并说明影响 |
| 空泛注释 | `# 处理数据` | 要么写清楚处理什么、按什么规则，要么删除 |

## 格式要求

- 中文注释使用全角标点；标识符、代码片段用反引号包裹。
- 行内注释与代码之间保留两个空格。
- 模块级 docstring 只描述模块职责与对外约定，不写修改历史。
- 函数 docstring 说明用途、参数、返回值、异常；不写作者、日期、版本。
- 不使用分隔线装饰（如 `# ===== 工具函数 =====`）；用命名与空行表达结构。

## 项目既定约束

- `.bat` 文件必须保持 ASCII + CRLF，不得添加中文注释。
- `knowledge/` 下的 `.json` 为数据资产，不得修改。
- `m7_venv/` 是运行环境目录（位于本地副产物区），不参与本规范。

## 本轮清理范围

本轮只处理**注释（`#`）与文档字符串**。字符串字面量与日志文案暂不处理，
以避免影响测试断言；如需处理，另行立项。
